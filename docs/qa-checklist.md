# Manual QA checklist

Run against the deployed site at its temporary `*.netlify.app` address before
any external tester is invited. The automated checks in CI cover type
checking, the build, internal links, axe rules on the built HTML and colour
contrast of the design tokens. They do not render pages, so everything below
needs a person and a real browser.

Record for each run:

- Date: `________`  Tester: `________`
- URL: `________`  Commit deployed: `________`

Mark each item pass, fail or not tested. A fail needs a note saying which
page, browser and viewport.

## 1. Browsers

Check the homepage and the Examples page in each. Check all six pages in at
least one desktop and one mobile browser.

| Browser | Platform | Home | Examples | Notes |
|---|---|---|---|---|
| Chrome (current) | Windows or macOS | | | |
| Firefox (current) | Windows or macOS | | | |
| Safari (current) | macOS | | | |
| Edge (current) | Windows | | | |
| Safari | iOS | | | |
| Chrome | Android | | | |

Fonts are system fonts and differ by platform. The hero headline is Didot or
Bodoni where installed and Georgia elsewhere; headings are Bahnschrift on
Windows and another condensed face elsewhere. Note anything that looks broken,
not merely different.

## 2. Responsive layout

Check at 375, 768, 1024 and 1440 px wide, and at one very wide size.

- [ ] No horizontal page scroll at any width on any page.
- [ ] Below 1024 px the header shows the Menu button; at 1024 px and above it
      shows the six links on one line.
- [ ] At 375 px the status strip is at most two lines.
- [ ] No heading, button or label is clipped or overlaps another element.
- [ ] The hero headline wraps cleanly and is not cut off.
- [ ] Code panels scroll horizontally inside themselves; long lines do not
      widen the page.
- [ ] Tables scroll inside their container at 375 px.
- [ ] The homepage limitations list reads correctly when its two columns stack.
- [ ] Page zoom at 200% on desktop: content reflows and stays usable.
- [ ] Phone in landscape: header and menu still usable.

## 3. Navigation and links

- [ ] Every header link opens the right page and is marked as current there.
- [ ] The Menu button opens and closes; every link in it works.
- [ ] The brand link returns to the homepage.
- [ ] In-page links work: homepage to `/examples/#invalid` and
      `/examples/#json-ir`, roadmap to `/get-started/#versions`.
- [ ] Every external link opens: the core repository, its issue tracker, the
      website repository, the Python venv documentation.
- [ ] Every link into the core repository opens a file at the pinned commit,
      not a 404. CI checks that these are pinned but does not fetch them.
- [ ] An unknown address shows the Page not found page.

## 4. Keyboard

Use only the keyboard, starting from the address bar.

- [ ] The first Tab shows the "Skip to content" link, and Enter moves focus to
      the main content.
- [ ] Tab order follows the visual order on every page.
- [ ] Focus is always visible: an orange outline on dark areas, a dark outline
      on light areas. Note any element where it is hard to see.
- [ ] The Menu button opens with Enter and with Space, the links inside are
      reachable with Tab, and the menu closes with Enter or Space on the
      button.
- [ ] Each code panel can be focused and scrolled sideways with the arrow keys.
- [ ] Nothing traps focus.
- [ ] Buttons and links activate with Enter.

## 5. Screen reader

Check the homepage, Get Started and Examples with at least one of: NVDA with
Firefox or Chrome on Windows, VoiceOver with Safari on macOS or iOS.

- [ ] The page title is announced and differs per page.
- [ ] Landmarks are present: the status region, header, main navigation, main,
      footer navigation.
- [ ] Each page has one level-1 heading, and the heading list reads as a
      sensible outline.
- [ ] The Menu button is announced as collapsed or expanded.
- [ ] The current page is announced in the navigation.
- [ ] Tables announce their column and row headers.
- [ ] Code panels are announced with their caption, and their content is
      readable line by line.
- [ ] Decorative squares, rules and crop marks are not announced.
- [ ] Note how the section numbers before headings and the brackets around
      status labels are read. They are generated by CSS and some screen
      readers speak them. Record whether this is confusing.

## 6. Content and metadata

- [ ] The status strip appears on every page, and the full hardware warning
      appears in every footer.
- [ ] The version numbers on Home, Get Started and the footer agree:
      distribution 0.1.0a1, language 1.1, IR schema 1.0.
- [ ] Following Get Started exactly, on a machine without RoboLang installed,
      produces the output shown on the page.
- [ ] Each page has a title, a meta description and a canonical URL.
- [ ] The favicon shows in the browser tab.
- [ ] With JavaScript disabled, every page and the menu still work.
- [ ] Printing a page (or print preview) gives readable output. Note problems;
      there is no print stylesheet yet.
